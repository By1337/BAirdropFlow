# Плейсхолдеры в параметрах компонентов

Значения компонентов заменяет их `Airdrop`, реализующий `PlaceholderApplier`.
`EventContext` используется для вызова обработчиков событий.

Числа и boolean можно передавать как обычные YAML-значения или строки с плейсхолдерами.
В строках, материалах, enum и элементах списков
также поддерживаются плейсхолдеры. Структура списков и карт остаётся YAML-структурой.

```yaml
args:
  rolls: '90'
  fill_ticks: '200'
  take_cooldown: '20'
  offset: '0;1;0'
  mask: gray_dye
  title: '<gold>Легендарный аирдроп'
nodes:
  looter:
    type: loot:looter
    loot_table: loot/default
    rolls: '{args:rolls}'
    fill_duration_ticks: '{args:fill_ticks}'
    take_cooldown_ticks: '{args:take_cooldown}'
    offsets: '{args:offset}'
    title: '{args:title}'
    obfuscation_materials: ['{args:mask}']
```

Вектор может быть целиком плейсхолдером или содержать плейсхолдеры отдельных осей:
`'{args:dx};{args:dy};{args:dz}'`. После подстановки ожидаются ровно три координаты
через `;`. Векторы блоков требуют целых чисел; дробные векторы — конечных чисел.

Обёртки находятся в `dev.by1337.baf.config.value`:
`IntValue.getInt(PlaceholderApplier)`, `DoubleValue.getDouble(...)`,
`BooleanValue.getBoolean(...)`, `StringValue.getString(...)`,
`Vec3iValue.getVector(...)`, `Vec3dValue.getVector(...)`,
`MaterialValue.getMaterial(...)` и общий `Parameter<T>.get(...)`.
Каждая обёртка сохраняет исходную строку, доступную через `source()`.

Константа разбирается и проверяется один раз при загрузке, а `get*` возвращает кэш,
не вызывая `PlaceholderApplier`. Строка с плейсхолдерами подставляется и проверяется
при каждом получении значения. Её результат не кэшируется между аирдропами.
Векторы разбираются напрямую, без повторного вызова `YamlDecoder`.

Счётчики кликов, таймеры, позиции, анимация и параметры лута получают
значения при создании компонента. Активный таймер не меняет свою длительность
при изменении аргумента; повторное создание компонента получает новое значение.
Боссбар читает настройки при обновлении, голограмма — строки при событии `update`,
GPS сохраняет динамическое обновление своей строки.

У схематики плейсхолдеры поддерживает только `offsets` на уровне компонента.
Смещение прибавляется к позиции аирдропа при создании `SchematicWriter`.
`path`, `no_replace`, `no_place` и `replace` разбираются один раз при загрузке
конфига, без поддержки плейсхолдеров. Готовая схематика используется повторно.

Ошибочная константа отклоняется при загрузке. Ошибочное значение после подстановки
сообщает исходное выражение, полученное значение и причину; ограничения поля
(например, положительное время или прогресс 0–1) проверяются и после подстановки.
