# Разброс лута

Компонент `loot:spreading` берёт предметы из таблицы лута и выбрасывает по одному
стаку через заданный интервал. Направление по горизонтали случайное, скорость
вверх задаётся отдельно. Старый `SpreadingItems-1.2.jar` устанавливать не нужно.

Пример ноды в `nodes` сценария:

```yaml
spread:
  type: loot:spreading
  loot_table: loot/default
  rolls: 20
  offsets: '0.5;1;0.5'
  interval_ticks: 2
  horizontal_speed: 0.4
  vertical_speed: 0.6
  pickup_delay_ticks: 20
  item_lifetime_ticks: 1200
  obfuscation_materials: [GRAY_DYE, LIGHT_GRAY_DYE]
  obfuscation_name: '<gray>Неизвестный предмет'
  trail_animation: example
  trail_interval_ticks: 1
  on_create: []
  on_spread_end: []
  on_remove: []
```

Создавай ноду через `spread create`, как другие компоненты. Числовые параметры,
смещение, ID таблицы/анимации и материалы поддерживают плейсхолдеры аирдропа.
Значения фиксируются при создании ноды. `rolls` — количество выборок таблицы с
повторениями; `0` и пустая таблица завершают разброс на первом тике.

`trail_animation` — ID существующей анимации из папки `particles`, без `.yml`.
Она проигрывается у каждого предмета, пока он летит; время анимации отсчитывается
от его выброса. Пустая строка выключает трейл. Интервалы и время жизни задаются
в тиках (20 тиков = 1 секунда).

Пустой `obfuscation_materials` выключает маскировку. С маскировкой в мире виден
один предмет-маска без метаданных оригинала и его количества. При подборе игрок
получает настоящий стак, включая имя и прочие метаданные. Если инвентарь заполнен,
остаток остаётся в мире под маской. Маски нельзя подбирать мобам и воронкам;
без маскировки работает обычный подбор. Предметы этой ноды не сливаются с другими.

`on_spread_end` срабатывает один раз после последнего выброса. Нода продолжает
обслуживать трейлы и подбор до исчезновения всех предметов, после чего удаляется
и вызывает `on_remove`. Ручной `spread remove`, уничтожение аирдропа и выключение
плагина убирают оставшиеся предметы и прекращают выброс. Поэтому уничтожение
аирдропа сразу в `on_spread_end` также уберёт только что выброшенный лут.
Предметы не сохраняются при выгрузке чанка/перезапуске сервера.

Редактор получает схему компонента с сервера. После обновления JAR плагина
достаточно обновить страницу редактора; пересборка и редеплой фронтенда не нужны.
